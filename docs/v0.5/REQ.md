# 需求文档：金流 v0.5 迭代（记账快捷输入：同上次日期 / 常用备注）

- 创建时间：2026-10-07 23:37
- 版本：v0.5
- 状态：已确认

## 1. 背景与目标

**一句话理解**：在「新增账单」弹层里加两个一键快捷 —— ① 日期行右侧一个「同上次 10-06」chip，点一下把日期设成上一笔记账的日期；② 备注输入框下面一排常用备注 chip（我手动收藏的 ★ + 按当前分类自动推荐的高频备注），点一下填入备注。

背景：当前填写账单存在两处反复操作 ——

1. **日期**：每开一次新增弹层，日期都默认「今天」。补记昨天的账要手动翻日历（v0.4 已把今天/昨天 chips 换成原生选择器，快捷性下降）。
2. **备注**：备注是自由文本，日常反复出现的就那几个（早餐、地铁、买菜…），每次都要重新逐字输入。

目标：把这两处从「多次操作 / 手打」降到「一次点击」，且**不改变任何现有录入流程**（不点快捷就完全和现在一样）。发布 v2.2.0。

## 2. 功能需求

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-01 | **「同上次」日期快捷 chip**：新增/编辑账单弹层的日期行右侧显示 chip「同上次 MM-DD」，值 = 我最近录入的那一笔账单的日期；点击后日期框变为该日期，chip 变选中态；日期行本身仍可点开原生日期选择器 | 高 |
| FR-02 | **最近一笔日期数据来源**：后端提供查询「我最近录入的一笔账单」（按 `created_at` 倒序取第一条，不限月份）的日期；无任何账单时前端不显示 chip | 高 |
| FR-03 | **常用备注 chips 展示**：备注输入框下方一行横向可滑动的 chip；候选 = 我手动收藏的（★ 标识，排最前、不受分类过滤）+ 当前所选分类下自动推荐的高频备注；最多显示 8 个 | 高 |
| FR-04 | **常用备注点击填入**：点击 chip 将备注框内容替换为该备注文本；空备注、与当前备注框内容相同的 chip 不算异常（幂等） | 高 |
| FR-05 | **常用备注手动管理**：备注框右侧「＋收藏」按钮把当前输入文字加入常用；长按 chip 弹出「取消收藏 / 不再推荐」（按该 chip 来源区分）；已被「不再推荐」的备注不再出现在自动推荐中 | 中 |
| FR-06 | **后端常用备注存储**：新增按用户存储的常用备注记录（收藏 / 隐藏两类），两个账号各自独立、互不可见；提供查询与写入接口 | 高 |
| FR-07 | **自动推荐统计口径**：最近 90 天内、在**当前分类**下出现 ≥2 次的备注，按「出现次数↓、最近使用↓」排序；空备注不进入候选 | 中 |
| FR-08 | **回归与版本**：不改动账单表字段与现有接口形态；mobile `tsc`/`jest` 通过且 `lint` 无**新增**问题（仓库既有 lint 基线 48 problems / 10 errors 不属本轮范围），backend `pytest` 全量通过；版本号升至 2.2.0（versionCode 220） | 中 |

## 3. 非功能需求

- **兼容性**：沿用 React Native 0.87，**不新增任何 npm 依赖**；后端沿用 FastAPI + SQLAlchemy + Alembic，不引入新依赖。
- **性能**：新增接口为单表单用户查询 + 小范围聚合，返回体积小；弹层打开时**最多发一次**快捷数据请求（收藏与分类候选合并返回），不随分类切换重复请求（客户端本地过滤）。
- **可用性**：新增接口失败时**降级**——弹层正常可用，仅隐藏 chip 区（不阻塞记账主流程，不弹错误）。
- **安全**：所有新接口走现有 JWT 鉴权，只读写当前登录用户自己的记录；备注长度沿用 255 上限。
- **数据兼容**：新表用**新增 alembic 迁移**创建，不修改历史迁移文件；不改动 `transactions` 表结构与既有接口响应。
- **范围**：仅 App（`mobile/`）；Web 端（`frontend/`，Capacitor 残留壳）与 Agent 侧不改动。

## 5. 约束与假设

- 「上一次」= **我最近录入的那一笔**（按 `created_at` 倒序），取其 `date` 字段；补录旧日期账单会改变 chip 值（已与用户确认）。
- 常用备注**跟账号绑定、存服务器**，两个账号各自独立、互不共享（已确认）。
- 自动推荐**按当前所选分类过滤**；手动收藏的 ★ 不受分类过滤，始终显示（已确认）。
- 弹层默认日期仍是**今天**，不会自动套用上次日期；chip 只填入，**不自动提交**。
- 视觉沿用 v0.1 风格 C「活力渐变」，不重出整套风格原型，仅对新增组件给出组件级说明。
- 只改 App；后端仅新增（表 + 接口），不改既有账单接口契约。
