这份样例在演示什么

  • 周期可配：周报 / 月报 / 季报 / 年报，报告始终覆盖「上一个完整自然周期」，不是滚动 30 天。
  • 时间可配：周报选星期几 + 时点；月报/季报/年报选每月几号 + 时点（1–28 号，避免短月歧义），默认 1 号 09:00。
  • 自动生成：沿用循环记账的服务端调度（启动即跑 + 每小时），关掉 App 也会生成；同一周期唯一，不会重复。
  • 财报内容：结余/储蓄率、环比、自动洞察、支出分布、周期内每周趋势、笔数统计；只含个人数据。
  • 入口：图表页右上角「📄 财报」，有新报告时红点 + 顶部提示条；历史报告在列表里，未读标记已读后消失。
  • 降级：列表离线读缓存；设置、生成等写操作离线置灰；生成失败只记日志，不影响记账主流程。

我的假设（请确认）

  • 报告范围只有个人账本：只统计自己的账单，不读取伴侣的数据，也不做双人对比。
  • 四套皮肤（极光 / 糖果 / 霓虹 / 浮雕）与亮暗模式全部跟随现有 theme token，不在页面里写死颜色；上面可以切换皮肤预览。
  • 「什么时候总结」= 服务端自动生成报告的时间；第一版不发系统推送，只在 App 内提示新报告。
  • 详情里的洞察由本地规则（环比、占比、极值）生成，不调用大模型，保证稳定与零成本。
  • 首个版本只做四种固定周期，不做「自定义 30 天 / 每两周」以及报告导出 PDF。

预期改动范围
