# 需求文档：Bookkeeping 原生 Android APP 重构 v0.1

- 创建时间：2026-08-15 22:10
- 版本：v0.1
- 状态：已确认

## 1. 背景与目标

现有「双人记账」项目为 Web 应用（前端 React + Vite + TS，后端 FastAPI + PostgreSQL，目前用 Capacitor 打包 Android APK，属"网页套壳"）。用户希望将其**重构为原生 Android APP**，获得真正的原生体验。

目标：在不改动后端的前提下，用 **React Native + TypeScript** 重写客户端，产出**仅 Android** 的原生 APP，**全部业务功能保留**，纯在线模式（不做离线同步），不做推送通知。

## 2. 功能需求

| 编号 | 需求描述 | 优先级 |

## 3. 非功能需求

- **性能**：账单列表长列表滚动流畅（建议 FlatList 虚拟化），启动时间可接受。
- **安全**：Token 存于安全存储（如 Keychain/EncryptedStorage）；请求走 HTTPS；退出登录清除本地会话。
- **可用性**：无网络时给出明确提示并可重试，不崩溃；加载态/空态/错误态完整。
- **兼容性**：minSdk ≥ 24（Android 7.0），目标 Android 14+；适配深色模式（跟随现有 Web 的主题能力）。
- **工程规范**：TypeScript 严格模式；目录结构与现有 Web 端对齐（api/types/store/components/pages），便于复用后端类型定义。

## 4. 验收标准

- [ ] 在 Android 模拟器/真机上可安装运行 APP，完成注册→登录→记账全流程
- [ ] 登录态持久化：杀进程重开仍保持登录，Token 过期自动刷新
- [ ] 首页可新增/编辑/删除交易，数据与后端一致（可与现有 Web 端交叉验证）
- [ ] 分类、统计、预算、储蓄、AI 助手、圈子、个人页、管理后台均可用且数据正确
- [ ] 断网时给出友好错误提示，恢复后操作正常
- [ ] 深色模式正常切换
- [ ] 可构建出 release APK（或至少 debug APK 可安装运行）

## 5. 约束与假设

- 后端 FastAPI API **完全不变**，客户端仅消费现有接口。
- 仅 Android 平台；不引入推送通知；不做离线记账与同步。
- 网络传输层直接复用现有 REST API；后端类型定义（`frontend/src/types/index.ts`）作为 RN 端类型参考。
- API 基础地址可通过配置文件指定（开发/生产环境分离）。
