# v0.19 需求：删掉「吃了什么」，只留商家 + 备注

> 版本 2.9.0 / versionCode 236。承接 v0.18 的商家 / 吃了什么 / 评价，但按用户实测反馈收敛：
> 「吃了什么」不好用；「评价」改回「备注」，备注承担消费明细。

## 背景

v0.18 把一笔账单拆成「商家 + 吃了什么 + 评价」三个维度。上线后用户口径变化：

- 「吃了什么」几乎不填，填了也是「食材 / AI / 剪发」这类杂物，没有统计价值；
- 真正想记的是「这钱花在什么上」，一段备注就够；
- 「评价」这个名字太窄，备注里通常写的是消费明细。

线上实际数据：2026-11-16 全库 2269 笔账单里只有 8 笔填过 `item`。

## 功能需求

- **FR-01 记一笔**：删除「吃了什么 / 玩了什么 / 项目」这一整块（含固定 chips 与自定义输入）；
  保留「商家(可选)」和「备注(可选)」。备注 placeholder 改为「牛肉面 / 卤味 / 有点咸」，
  提示可以写消费明细。提交 payload 不再带 `item`。
- **FR-02 列表**：标题 `商家 || 分类`；副标题 `备注 || （有商家时）分类 || 无备注`。
- **FR-03 图表**：支出分布从「分类 / 商家 / 菜品」改为「分类 / 商家」两档；
  「旧备注 N 条未整理 · 去整理」入口从菜品档移到商家档（仍需保留整理入口）。
- **FR-04 整理旧备注**：每条只能选「商家 / 备注 / 跳过」三选一；
  不再有「项目」「两者同选」。
- **FR-05 财报**：吃喝卡删除「最常吃 X」一条洞察，保留「最常去 X」与「餐饮 N 次平均每次」；
  最大单笔支出的标题优先级改为 商家 → 备注 → 分类。
- **FR-06 数据保留**：存量 `item` 不为空时，迁移合并进 `note`
  （备注为空直接搬过去，否则写成「项目 · 备注」）并置 `note_kind='evaluation'`；
  随后删除 `transactions.item` 与 `note_cleanup_items.old_item/new_item`。
- **FR-07 旧客户端**：2.8.x App 仍可记账（多余 `item` 字段被忽略）；
  `GET /stats/breakdown?dimension=item` 保留但返回空排行，避免旧 App 报错。
- **FR-08 CSV 导入**：仍识别「项目 / 吃了什么 / 菜品」表头，但把该列合并进备注，不丢信息。

## 非功能

- 不新增接口前缀，无需改 nginx 白名单。
- 统计口径仍是「仅本人」；商家排行只统计「餐饮」。
- 迁移在 SQLite 上验证 upgrade → downgrade → upgrade 可重复执行。

## 验收标准

1. 2.9.0 上记一笔只能看到「商家 + 备注」两块，保存后 `GET /transactions` 无 `item` 字段。
2. 老账单里原来的「卤味」等 item 出现在备注里，账单列表副标题可见。
3. 图表页只剩「分类 / 商家」；商家档底部有旧备注整理入口。
4. 整理页选商家后保存，`POST /transactions/notes/reclassify` 只发 note/action/merchant/batch_key。
5. 财报吃喝卡只有商家洞察，不再出现「最常吃」。
6. 后端 `pytest` 全绿；App `tsc --noEmit` / `jest` 全绿，eslint 无新增 error。

## 不做

- 不重新设计备注的智能解析（备注就是自由文本）。
- 不回填历史财报快照里的 `items` 字段（旧报告是快照，App 按可选字段忽略）。
