一句话理解

我理解你要的是：你把代码提交（上传）到 GitHub 之后，VPS 自己定时去拉取，自动重建后端、跑数据库迁移、重建并发布 Web 前端；部署失败就停下来报警等你处理。不需要你在服务器上手动操作。

目标与场景

  • 谁：你自己开发并上传代码；服务器无人值守。
  • 什么时候用：每次改完代码提交到 main 分支之后。
  • 解决什么问题：现在每次发布都要在本机打包 → scp 上传 → 手工 rsync / 重建 / 跑迁移（本次 v0.5 我就是这么发的），步骤多、容易漏。
  • 不解决：Android APK（服务器只有 2 vCPU / 1.9G 内存，且无 JDK/Android SDK，构建 APK 仍在你本机做，OTA 仍走 app.xyvora.me）。

核心流程

1. 你 push 到 GitHub main
→
2. VPS 每 2 分钟 git fetch
→
3. 有新提交？比对变更目录
→
4a. backend/ 变了 → 重建容器 + 跑迁移
4b. frontend/ 变了 → npm ci(按需) + vite build + 发布
4c. nginx.conf 变了 → nginx -t 通过才 reload
→
5. 健康检查 → 记录成功（或失败报警并停手）
没有新提交时整轮几乎零开销（一次 git fetch，约 0.3 秒），不会反复重建。

部署判定表（改哪里 → 做什么）

变更路径自动动作耗时量级
backend/**备份 .env → rsync 源码 → docker compose build backend → alembic upgrade head（迁移前自动存一份数据库快照）→ 重启容器 → /health 探活1.5–3 分钟（首次构建拉依赖更久）
frontend/**rsync 源码（保留 node_modules）→ 若 package-lock.json 变了才 npm ci → vite build（PUBLIC_HOST=api.bookkeeping.neobee.top）→ 发布到 /var/www/frontend首次含 npm ci 约 3–6 分钟；后续约 30 秒
deploy/nginx.conf复制到 sites-available → nginx -t 通过才 reload（不通过就回退配置）秒级
mobile/**、docs/**不部署（App 走 APK/OTA；文档不影响运行）—

命令样例（你在本机/我都可以用）

日常
# 当前部署状态（最近成功/失败、有没有待部署提交）
sudo /opt/bookkeeping/ci/deploy.sh --status

# 不想等下一个 2 分钟周期，立刻部署一次
sudo systemctl start bk-deploy.service

# 看部署日志
tail -f /var/log/bk-deploy.log
journalctl -u bk-deploy -n 50 --no-pager
异常处理
# 某次提交部署失败后，修好代码、重新 push 即可；
# 想重试同一个提交：
sudo /opt/bookkeeping/ci/deploy.sh --retry

# 临时停掉自动部署（比如你在服务器上手动调试）
sudo systemctl disable --now bk-deploy.timer

# 恢复自动部署
sudo systemctl enable --now bk-deploy.timer

我的假设（不对请直接说）

  • 仓库是 公开 的（已确认），所以 VPS 拉代码 不需要任何凭据；我不会在服务器上放你的 GitHub 令牌。
  • 部署脚本放在 仓库之外（/opt/bookkeeping/ci/），不随代码自更新 —— 避免"仓库被改写就自动执行任意脚本"。仓库里存一份副本仅供版本管理。
  • 只跟 main 分支；其他分支（含 codex/*）不部署。
  • 轮询间隔 2 分钟（可改），部署过程用文件锁互斥，不会两轮撞车。
  • 失败语义：记录失败提交并停止重试（避免每 2 分钟反复折腾），日志 + ALERT.txt 报警；你处理后 --retry 或 push 新提交。
  • 迁移自动执行，但执行前自动存一份数据库快照（保留最近 5 份），以便回退。
  • 报警只落到日志/文件（服务器未配邮件、微信等通道）；如果需要外部通知，下个版本再加。

暂不做

  • 不在服务器上构建 APK（无 JDK/SDK，内存也不够）——APK 仍由你本机构建后推 OTA。
  • 不用 GitHub Actions（你选的是 VPS 轮询；也不需要把私钥存到 GitHub）。
  • 不做自动回滚（你选的是"失败停手 + 人工处理"）；也不做 pytest 门禁。
  • 不动数据库里的业务数据，也不重建 nginx 站点/证书。
  • 不做多环境（测试/预发）：只有这一套生产环境。

设计确认（已答，记录在此）

部署范围：后端 + Web 前端 + 自动跑迁移 ✅
触发方式：VPS 定时轮询 ✅ GitHub Actions 触发 轮询 + 立即部署命令（本次已含）
测试门禁：不加门禁，直接部署 ✅ 后端 pytest 门禁
失败处理：停下来报警，人工处理 ✅ 自动回滚上一版
还剩一个开放项：APK 2.2.0 仍未构建（v0.5 的成果，本机缺 JDK/Android SDK）。这不属于本次 CI/CD 范围，等你有空决定（我自动装工具链构建 / 你用 Android Studio 构建）。
