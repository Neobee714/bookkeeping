# v0.20 需求：UX 走查修复 —— 弹层按钮吸底 + 小光 Markdown 渲染

来源：2026-11-16 UX 走查（dogfood-ux-2026-11-16）两个高优先级问题。
样例：`docs/v0.20/preview/ux-fix-sample.html`（已获用户确认「可以」）。
版本线：2.9.0 → 2.9.1（versionCode 236 → 237），本轮不发 OTA。

## FR-1 记账弹层「确认新增/保存修改」按钮吸底常驻

- FR-1.1 按钮移出 ScrollView，落进弹层固定 footer（`flex:none`），内容区独立滚动；任何滚动位置下按钮完整可见。
- FR-1.2 footer 顶部加分隔线（用 `colors.border`，非渐变卡语境）；底部内边距 20–24px（手势区让位）。
- FR-1.3 `errorMessage`（提交失败提示）随按钮进 footer，始终可见；金额校验的行内红字提示位置不变。
- FR-1.4 键盘弹出行为不变（KeyboardAvoidingView behavior="height"），按钮随弹层上移不被键盘遮挡。
- FR-1.5 编辑模式按钮文案「保存修改」逻辑不变；`submitting` 禁用态不变。
- FR-1.6 弹层整体高度上限 92% 不变；内容多时滚动的是表单区。

## FR-2 小光回答的 Markdown 渲染

- FR-2.1 AI 消息气泡内渲染轻量 Markdown：加粗 `**x**`、无序列表 `- ` / `* `、表格（`| a | b |` + `|---|` 分隔行）、行内代码 `` `x` ``、段落/换行。
- FR-2.2 不渲染：图片、HTML、链接跳转（链接按纯文本显示）；未知语法一律按纯文本直出（不丢字）。
- FR-2.3 表格窄屏（320 宽）允许横向滚动，不挤压气泡宽度；表头用 `surface` 底色 + `border` 描边（皮肤 token，不写死颜色）。
- FR-2.4 用户消息气泡保持纯文本；工具标签、「记账成功」徽标、空态、示例 chips 不动。
- FR-2.5 自研轻量解析（纯函数 + 渲染组件），不引第三方 markdown 依赖。

## 非目标

- 不改 AI 输出风格 / prompt / 工具；不改消息气泡布局与配色。
- 不动其他弹层（循环记账等）；不动后端。
- 不发版：无 OTA、无 APK 构建；停在本地门禁。

## 验收标准

1. 记账弹层打开即见「确认新增」；表单滚动到底按钮位置不动（对照样例屏②）。
2. 编辑账单弹层同样吸底，按钮文案「保存修改」。
3. 提交失败（断网点提交触发错误）时 footer 内可见错误提示。
4. 小光对含 **加粗**、列表、表格的回答渲染正确；纯文本回答原样显示；渲染组件单测覆盖加粗/列表/表格/行内代码/纯文本/混合。
5. 本地门禁全绿：`cd mobile && npx tsc --noEmit && npx jest && npx eslint .`（eslint 仅比对新增告警）。

## Q&A

| 问题 | 结论 |
| --- | --- |
| 循环记账弹层「保存」是否顺带吸底？ | 本轮不含（样例假设第 3 条，用户未提出修改） |
| markdown 是否渲染斜体/标题/链接？ | 不渲染标题与链接；斜体不在范围，按纯文本 |
