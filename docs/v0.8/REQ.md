- 创建时间：2026-10-23 14:48

## 1. 背景与目标

**一句话理解**：断网时首页还能看到上次的账单和汇总，分类还能用，也能继续记一笔；
这笔账先存在手机里（标记「待同步」），恢复网络后自动上传，不会重复。

背景：

1. 首页/统计页每次进入都直接请求 API，断网（地铁、电梯、弱网）时是错误页，连历史都看不到。
2. 新增账单必须等 POST 成功；失败时弹层里的输入只能重来，记一笔会被打断。
3. 记账发生在移动场景，离线是高频需求；当前没有任何本地缓存或队列。

目标：离线可读（最近看过的月份/分类/汇总）、离线可记（新增进队列）、恢复后自动同步；
不引入编辑/删除的离线冲突处理（这两个操作仍要求联网）。

## 2. 功能需求

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-01 | **首页缓存**：按「用户 + 自己/伴侣 + 月份」缓存账单列表与月度汇总；再次进入先渲染缓存，再后台刷新 | 高 |
| FR-02 | **分类缓存**：分类表缓存到本地；离线打开新增弹层时用缓存分类，不因网络失败而无法记账 | 高 |
| FR-03 | **离线新增**：新增账单在离线或请求失败（无响应/超时）时写入持久队列，生成 `client_id`，列表立即显示「待同步」，汇总按本地增量更新 | 高 |
| FR-04 | **自动同步**：App 启动、网络恢复、回到前台时按创建顺序逐条上传；成功后移除队列并刷新首页；4xx 标记失败并保留，网络/5xx 停止本轮、稍后重试 | 高 |
| FR-05 | **幂等**：后端 `transactions.client_id` 按用户唯一；重复提交同一 `client_id` 返回已有记录，不产生重复账单 | 高 |
| FR-06 | **全局状态**：底部悬浮横幅显示「离线模式 · N 笔待同步」「正在同步」「N 笔同步失败」，可点击重试（不压各页面 header） | 中 |
| FR-07 | **统计页降级**：网络失败时读取缓存的月度汇总与最近 6 个月趋势（各月汇总缓存）；无缓存时保持现有错误态 | 中 |
| FR-08 | **编辑/删除**：离线时明确提示「需要联网」，不静默失败、不进入本地队列 | 中 |
| FR-09 | **发布**：新增 `@react-native-community/netinfo` 原生依赖；版本升至 2.3.0 / versionCode 223；必须重发 APK | 高 |

## 3. 非功能需求

- **用户隔离**：缓存与队列 key 均带 `userId`；切换账号互不可见。
- **容量**：队列上限 200 条，超出拒绝并提示；缓存按月保留，版本号变更时整体失效。
- **安全**：缓存与队列存 AsyncStorage（应用私有目录，不加密）；不在日志中打印金额/备注；
  登出清除该用户缓存，但保留未同步队列（同一用户重新登录后可继续同步）。
- **兼容**：`client_id` 为可选字段，旧版 App 不传仍可正常创建；后端迁移只加列/约束，不改历史数据。
- **不新增后端依赖**；不改变现有接口路径与响应结构（仅在 Transaction 中增加 `client_id` 字段）。
- **可观测**：同步失败保留错误原因（HTTP 状态/网络错误），横幅可查看；不引入外部监控服务。

## 5. 约束与假设

- 离线只处理「新增」：新增是追加操作，按用户隔离，不存在两端覆盖冲突。
- 编辑/删除离线需要版本号/冲突策略，本轮明确不做。
- 图片头像、AI 助手、OTA 检查仍要求联网；离线时保持现有错误提示。
- 缓存是「上次成功看到的数据」，可能过期；横幅会提示离线，不假装是最新。
- 本轮不做后台同步（App 被杀后不保证自动上传）；下次打开/回前台会继续。
- **首次使用必须先联网一次**：没有任何缓存时，离线打开首页/新增弹层只能看到空态或错误提示。
- 缓存与队列存 AsyncStorage（应用私有目录，不加密）；同一设备上的其他 App 读不到，但 root/备份工具可读。
