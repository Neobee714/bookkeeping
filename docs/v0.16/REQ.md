# v0.16 需求：循环记账

- 创建时间：2026-11-10
- 起点版本：2.5.2 / versionCode 230
- 目标版本：2.6.0 / versionCode 231
- 样例：`docs/v0.16/preview/recurring.html`（用户已确认「可以，按这个做」）

## 背景

房租、宽带、工资、会员费这类账单每月固定发生，现在每次都要手动记一遍。用户希望只配置一次，
到期自动生成真实账单；生成的账单与手动记录完全等价，可以编辑、删除。

## 功能需求

- **FR-01 规则列表**：规划页新增第三个分段「循环」，列出当前用户的规则，展示分类图标、
  备注（无备注时用分类名）、频率文案、金额、下一次到期日与启用开关。
- **FR-02 新建规则**：支出/收入、金额、备注（可选）、分类、重复频率、首次日期。
  首列语义由「首次日期」锚定：填 11-01 即每月 1 号；每周取该日期的星期几；每年取该日期的月/日。
- **FR-03 频率集合**：每天 / 每周 / 每月 / 每年 四种，第一版不做「多长间隔」（如每两周）。
- **FR-04 自动生成**：服务端在到期日生成一笔真实账单（含收入），关掉 App 也会生成。
  同一规则同一天最多一笔（幂等）。
- **FR-05 月末边界**：每月/每年规则若锚定 29–31 号，短月按当月最后一天生成
  （31 号 → 2 月 28/29 日、4 月 30 日）；闰年 2-29 的年度规则在平年取 2-28。
- **FR-06 暂停与恢复**：关闭开关后不再生成；重新开启从下一个到期日开始，不补暂停期间的账。
- **FR-07 编辑与删除**：可改金额、备注、分类、频率、首次日期；删除规则只停止未来生成，
  已生成的账单保留（账单与规则的关联置空）。
- **FR-08 首页标识**：由规则生成的账单在首页带「循环」小标，与手动记账区分。
- **FR-09 补跑上限**：容器长时间停机后最多回溯 90 天生成；更早的到期日直接跳过，不刷屏。
- **FR-10 隔离**：规则只属于创建者本人，伴侣看不到规则本身；生成的账单按现有双人账本规则共享可见。
- **FR-11 离线降级**：规则列表离线时读本地缓存并提示；新建/编辑/删除需要联网，
  离线时按钮置灰。循环规则不进入离线补记队列。

## 非功能需求

- 生成任务失败不得影响 API 主流程：调度循环内部捕获异常并记录日志。
- 生成必须幂等：重复执行、容器重启、并发启动都不得产生重复账单。
- 单次生成上限：每个规则一次最多补 400 笔（防御性保护）。
- 新增接口失败必须静默降级，不阻塞首页记账主流程。
- 规则数量上限：每用户 50 条（超出返回 400，避免误建导致刷屏）。

## 验收标准

1. 新建「每月 1 号 / 3200 / 居住 / 支出」规则后，`next_run_date` 为下一个 1 号；
   把系统日期推进到该日，`generate_due` 生成一笔 3200 的支出账单，且第二次执行不再新增。
2. 锚定 31 号的规则在 2 月生成日期为 28（或闰年 29）；4 月为 30。
3. 关闭开关后到期不生成；重新开启后不补暂停期间的账。
4. 删除规则后历史账单仍在，且其 `recurring_rule_id` 变为 `null`。
5. 另一用户访问/修改/删除该规则返回 404；规则不出现在伴侣的列表里。
6. 首页由规则生成的账单显示「循环」小标，手动记账没有。
7. 离线打开规划页：显示缓存列表 + 离线提示，新建按钮置灰，不崩溃。
8. `pytest`、`tsc --noEmit`、`jest`、`eslint` 全部通过（eslint 仅允许既存基线）。

## 不在本次范围

- 结束日期 / 只跑 N 次、提前提醒与通知推送。
- 「记到伴侣名下」的循环、多账本切换。
- 按工作日 / 每月最后工作日等复杂日历规则。
- 历史账单批量回填：首次日期在过去时，从下一个**未来**到期日开始生成。
- iOS 端独立适配（表单与日期选择器沿用现有弹层实现）。

## Q&A（已确认）

| 问题 | 结论 |
| --- | --- |
| 入口放哪 | 规划页第三段「循环」，不加底部 Tab |
| 频率范围 | 每天 / 每周 / 每月 / 每年，锚定首次日期 |
| 谁生成 | 服务端每天（每小时检查）生成，关 App 也记 |
| 补跑 | 最多回溯 90 天 |
| 暂停语义 | 暂停期间不补账，恢复从下一个到期日继续 |
| 删规则 | 不删历史账单 |
| 双人 | 规则私有，生成的账单共享可见 |
| 离线 | 只读缓存，写操作需联网 |
