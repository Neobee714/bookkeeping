我理解的需求（请确认）

  • 入口：规划页在「预算 / 储蓄」后加第三个分段「循环」，不新增底部 Tab。
  • 频率：每天 / 每周 / 每月 / 每年，另有工作日类（每个工作日 / 每月最后一个工作日 / 每月第 N 个工作日；工作日=周一至周五，不含法定节假日），具体日子由「首次日期」决定 —— 首次填 11-01 就是每月 1 号，填 11-05 就是每月 5 号；每周取首次日期是星期几。
  • 生成：服务端每天检查一次到期规则并落真实账单（含收入），关掉 App 也会记。补跑最多回溯 90 天，避免长时间停机后一次刷出几百笔。
  • 月末边界：31 号的规则在 2 月按当月最后一天生成（2-28/29），4 月按 4-30。
  • 暂停/恢复：开关暂停后不再生成；恢复时从下一个到期日开始，不补暂停期间的账。
  • 编辑/删除：规则可改金额、备注、分类、频率、首次日期；删规则只停止未来生成，已生成的账单保留。
  • 已经生成的账单：和手动记的完全一样，可编辑、可删除；首页带一个「循环」小标，便于和手记区分。
  • 双人账本：规则只记自己（同语音记账），伴侣能看到生成的账单和金额，但看不到规则本身。
  • 离线：循环规则需要联网新建/修改；离线时列表读缓存、按钮置灰并提示。不进入现有离线补记队列。

不在这次范围

  • 结束日期 / 只跑 N 次（先用暂停或删除控制）。
  • 到期前提醒、通知推送。
  • 「记到伴侣名下」的循环、多个账本切换。
  • 按工作日/每月最后一个工作日这类复杂日历规则。
  • 历史账单批量回填（新建规则只从首次日期开始向后生成）。

技术形态（供你确认口径，细节写进 ARCH）

  • 后端：新表 recurring_rules + 迁移；GET/POST/PATCH/DELETE /recurring；账单表加 recurring_rule_id 与 UNIQUE(rule_id, date) 做幂等，重复生成不会多记。
  • 调度：FastAPI 启动时起一个 asyncio 后台循环，每小时跑一次到期生成（当前容器是单进程 uvicorn，不需要额外依赖或 cron）。
  • App：src/api/recurring.ts、RecurringSheet 复用记账弹层的表单与分类宫格、PlanScreen 加分段、首页 TransactionItem 加「循环」小标。
  • 版本：2.5.2 → 2.6.0（versionCode 230 → 231）；后端有迁移，push 后由 CI 自动部署。
需要你确认：这份样例是否符合你要的「循环记账」？确认后我再按流程写 REQ/ARCH/CHECKLIST 并派子 Agent 实现。 如果频率只想要「每月」，或者入口想放首页，现在说更省事。
