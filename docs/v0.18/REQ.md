# v0.18 需求：商家、吃了什么与评价

- 创建时间：2026-11-12
- 起点版本：2.7.0 / versionCode 233（v0.17 尚未发布）
- 目标版本：2.8.0 / versionCode 234
- 样例：`docs/v0.18/preview/merchant.html`（已按「备注改为评价」修订）

## 背景

现在一笔餐饮支出只有一个备注，有时写店名，有时写「面 / 粉」，有时写「有点咸」。
看图表时无法分开回答两个问题：**常去哪家店**、**爱吃什么**。

## 已确认的口径

- `餐饮` 分类不动，预算和总支出仍按分类统计。
- 新增 **商家** 和 **吃了什么** 两个可选字段。
- 原 `note` 改为 **评价**（自由文本，例如「有点咸，面很筋道」），不参与排行。
- 旧备注**不自动拆分**；提供「整理旧备注」入口，由用户逐条确认后批量应用。
- 只处理个人账本；伴侣统计沿用现有「我的 / TA」视图，但本功能不做家庭合并报告。
- 本次按用户要求，整理撤销完成后随 2.8.0 / 234 发布 OTA。

## 功能需求

- **FR-01 记一笔**：支出/收入表单增加「商家」「吃了什么」两个可选输入；原「备注」标签改为「评价」。
  - 商家：文本输入 + 最近 90 天该分类的高频商家 chips。
  - 吃了什么：固定 chips（面 / 粉 / 饭 / 火锅 / 烧烤 / 咖啡 / 奶茶等）+「自定义」。
  - 评价：自由文本，最多 255 字。
  - 三者都可留空，不阻塞记账。
- **FR-02 快速输入**：`/transactions/quick-inputs` 除现有备注外，返回按分类的商家与菜品候选
  （各最多 6 个，90 天窗口），失败时静默降级。备注 chips 只统计已确认的评价（`note_kind='evaluation'`），
  旧备注不会再次作为「评价」候选出现。
- **FR-03 图表维度**：支出分布卡改为「分类 / 商家 / 菜品」三档；商家 / 菜品档只统计「餐饮」分类。
  - 分类：沿用现有分类支出。
  - 商家：按金额降序，显示金额、次数、人均；未填商家的账单不计入，并给出说明。
  - 菜品：按金额降序，显示金额、次数、人均；未填「吃了什么」的账单不计入。
  - 旧备注（未整理）不计入商家/菜品，菜品档给出「旧备注 N 条未整理 · 去整理」入口。
- **FR-04 财报**：个人财报快照增加商家与菜品排行，以及最多两条吃喝洞察：
  「最常去 X」/「最常吃 X」/「外食 N 次，平均每次 ¥Y」。
- **FR-05 整理旧备注**：列出 `note_kind IS NULL` 的历史备注（按次数/金额排序），
  每条可选：商家 / 吃了什么 / 两者 / 评价 / 跳过；保存后批量应用到所有同名旧账单。
  - 商家：写入 `merchant`，清空 `note`。
  - 两者：写入 `merchant` + `item`，清空 `note`。
  - 吃了什么：写入 `item`，清空 `note`。
  - 评价：保留 `note`，标记 `note_kind = 'evaluation'`，不进入排行。
  - 只影响统计字段，不改金额、日期、分类。
- **FR-06 隐私**：商家/菜品/评价都只属于当前用户；整理接口只能处理自己的账单；
  报告仍只统计本人。
- **FR-07 离线**：新增/编辑账单的离线队列带上商家与菜品；整理和统计维度查询需要联网，
  离线时读列表缓存并禁用写操作；接口失败不阻塞记账主流程。
- **FR-08 主题**：三个新界面全部使用现有 skin token，四套皮肤（极光/糖果/霓虹/浮雕）可读。
- **FR-09 撤销整理**：同一次保存的多条 `reclassify` 共用一个 `batch_key`，后端记录批次和每行原值/新值；
  整理页顶部显示「上次整理 · 时间 · 条数」，可一键整批恢复。
  - 只恢复仍保持整理后状态的账单；整理后又被编辑过的账单跳过，不覆盖用户新改动。
  - 撤销后账单重新回到旧备注候选；已生成的财报快照不回溯。
  - 接口：`POST /transactions/notes/undo`，不传 `batch_id` 时撤销最近一批。

## 非功能需求

- 旧数据迁移只加可空列，不改写历史 `note`；迁移必须可 upgrade/downgrade。
- 整理接口按 `user_id` + `note` + `note_kind IS NULL` 限定，避免误改新记录。
- 统计与整理查询必须带 `user_id` 条件；单用户数据量小，不做额外索引也可接受。
- 新接口失败必须静默降级，不阻塞首页/图表/财报主流程。
- 版本三处：`build.gradle` versionCode/versionName；`app.json` displayName 保持「拾光」。

## 验收标准

1. 记一笔填写商家「和府捞面」、吃了什么「面」、评价「有点咸」后保存；列表/详情能看到三项，
   `note_kind = 'evaluation'`，商家与菜品进入各自排行。
2. 图表切到「商家」：和府捞面显示金额/次数/人均；未填商家的账单不出现在排行。
3. 图表切到「菜品」：面/粉/饭分别聚合；旧备注未整理时不出现在排行，并显示整理入口。
4. 财报详情出现「最常去」「最常吃」洞察；没有商家/菜品数据时该卡隐藏，不报错。
5. 整理「和府捞面」为商家：12 条旧账单的 `merchant` 变为和府捞面、`note` 清空，
   商家排行出现该店；账单金额/日期不变。
6. 整理「有点咸」为评价：保留 `note`，`note_kind='evaluation'`，不进入商家/菜品排行。
7. 伴侣的账单不会出现在当前用户的商家/菜品统计里；整理接口不能改伴侣数据。
8. 离线打开图表：显示缓存；商家/菜品请求失败不让整页报错；整理页写操作置灰。
9. 四套皮肤下记一笔、图表、整理页、财报吃喝卡对比度正常，无写死颜色。
10. `pytest`、`tsc --noEmit`、`jest`、`eslint` 全部通过（eslint 仅允许既存基线）。
11. 一次保存 12 条旧备注后顶部出现「上次整理 · 12 条」；点撤销后 12 条全部恢复，商家/菜品排行回到整理前。
12. 整理后又编辑过其中一条，再撤销：其余恢复，被编辑的那条跳过且不被覆盖。

## 不在本次范围

- 自动拆分旧备注、AI 识别商家/菜品。
- 商家独立实体表、别名合并、地图/评分。
- 按商家/菜品做预算，或跨商家对比。
- 语音记账自动拆分（识别文本仍进评价，确认页可手改）。
- 无。本次包含 APK 构建与 OTA 发布。
