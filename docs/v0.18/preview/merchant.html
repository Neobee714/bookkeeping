这个样例在演示什么

  • 记一笔：分类仍是「餐饮」；新增可选的「商家」和「吃了什么」，原备注改为「评价」。商家按最近 90 天常用排序，菜品给固定 chips，评价是自由文本、不参与排行。
  • 图表：原「备注排行」改为「分类 / 商家 / 菜品」三档；评价不参与排行。商家看金额、次数、人均；菜品看金额、次数，解决「爱吃面还是粉」。
  • 财报：在现有报告里加「吃喝洞察」和「常去的店 Top3」，与本月总支出、储蓄率放在同一份报告里。
  • 旧数据：只加可空字段，旧备注原样保留；未分类前默认不计入商家 / 菜品排行，账单里仍能看到原文，不强制迁移。
  • 整理旧备注：图表/财报给入口，逐条选「商家 / 吃了什么 / 评价 / 跳过」，可批量应用到同名账单；系统只给建议，不自动猜。样例显示的是已选中状态，实际打开默认不选。
  • 撤销：一次保存归为一批；页面顶部显示「上次整理 · 时间 · 条数」，点「撤销」整批恢复原值。整理后又被编辑过的账单会跳过，不覆盖新改动。

我的建议

  • 数据模型是「商家 + 吃了什么 + 评价」：前两个进入排行，评价只跟着账单。商家名先不做独立实体表，靠 chips 和手输控制一致性。
  • 「吃了什么」以点选 chip 为主，「自定义」再手输，这样「面 / 粉 / 饭」的统计口径稳定；想写「牛肉面」也可以，但会单独成一项。
  • 第一版不做：旧备注自动拆分（只提供人工整理入口）、AI 自动识别商家、商家地图/评分、按商家做预算。

预期改动

  • 后端：`transactions` 加可空 `merchant`、`item` 两个字段 + 迁移；`note` 保留为评价；记账/编辑/导入接口接收三个字段；统计加商家 / 菜品维度；财报快照加吃喝洞察。
  • App：记一笔弹层加商家、吃了什么、评价；图表页加维度切换；财报详情加吃喝卡；整理旧备注页面；离线队列带上商家与菜品。
  • 版本：2.8.0 / versionCode 234（已实现，含整理撤销；待发布 OTA）。
